# DarkDNA-Observer v2 migration plan

## Compatibility policy

Existing CLI commands and the default sequence-first pipeline remain public. Scientifically misleading fields are not silently removed: a canonical replacement is added, the old name is retained as a deprecated alias where feasible, and every alias carries a machine-readable warning/status. An unavailable method produces `NA`, not zero.

## Statistical migration

- Read `empirical_p_value_status` and `empirical_p_value_reason` before using any p-value.
- Primitive-score construction now emits `NA` p-values because no null is defined there.
- Matched-null p-values are emitted only when at least one distinct control exists and include null model ID, sample size, tail, and reason.
- Residual rows report the z-score method. Conditional residual z-scores, held-out quantile residuals, and conformal intervals require independent chromosome/block groups.
- `classical_model_global_r2` may be negative under cross-validation. It must not be clamped to zero or interpreted per region.
- FDR remains a merged-locus operation. Window-level rows are discovery diagnostics.

## Output additions in Phase 1

- `primitive_score_manifest.json` now documents orientations, component availability, correlation/double-counting audits, covariance-aware combination, and p-value policy.
- `negative_evidence.json` and `negative_evidence.parquet` are written with region cards.
- Sequence features add compression calibration, numeric-walk registry, multiscale diagnostics, DNA-shape predictor records, and structure-specific non-B records.
- Residual outputs add conditional variance, quantile/conformal, heteroscedasticity, bootstrap, p-value provenance, and canonical R2 fields.

## Downstream migration checklist

1. Prefer canonical fields and treat aliases as temporary.
2. Preserve `NA`; do not coerce unavailable scientific values to zero.
3. Filter p-values by an available explicit-null status.
4. Treat all primitive values as screening priorities, never probabilities.
5. Use structure-specific non-B records; never reconstruct the retired aggregate.
6. Require `multiscale_texture_status=available` before using the multiscale score.
7. Count and test merged loci, not overlapping windows.
8. Surface negative evidence and downgraded candidates in every downstream report.

## Phase 2 null migration

- `matched_controls_v1` remains a deprecated registry alias. Canonical candidate
  summaries use `severe_null_panel_conservative_aggregate`.
- Read `available_null_models`, `missing_null_models`, `null_model_count`,
  `null_model_agreement`, and `null_model_conflict` before promotion.
- `matched_null_zscore` now receives the conservative minimum survival z-score
  across calibrated named table-based nulls. Detailed distributions are in
  `severe_null_details.parquet`.
- Sequence-transformation and evolutionary-process nulls are benchmark outputs;
  they are not counted as candidate-level nulls unless actually run.
- `matched_nulls.parquet` and `null_model_summary.parquet` remain compatibility
  outputs.

## Phase 3 Mode B migration

- Mode B is disabled by default; the existing Mode A pipeline is unchanged.
- Enable `analysis_modes.sequence_indifferent.enabled` or invoke a Mode B command.
- `sequence_vs_quantity_scores.parquet` contains separate Mode A and Mode B
  columns. There is no combined score.
- Transformation sensitivities are model-based and not causal probabilities.
- Missing optional tracks emit `NA`, an unavailable status, and a reason.
- Region cards add Mode B fields only when a matching interval result exists.

Phases 4–8 remain deferred until their data validation and negative-control
contracts are implemented.
